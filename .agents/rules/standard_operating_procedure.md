# 안티그라비티 작업 지시 표준 운영 규칙 (SOP)

본 프로젝트(Wuthering Waves TCG / 명조: 대결 TCG)의 모든 코드 수정, 리팩토링, 버그 수정, 기능 추가 작업 시 아래 규칙을 **최우선 기본 원칙(Default Rules)**으로 항상 준수해야 합니다.
(근거 문서: `_docs/안티그라비티_작업지시_표준문구.md`, `_docs/명조_대결_TCG_작업_계획서.md` 「재발 방지 규칙」)

## 1. 진행 기본 원칙
1. **지시된 한 단계만 수행 (One Step at a Time)**: 한 번에 지시된 단계 하나만 수행하고 완료 시 멈춰서 보고.
2. **코드 수정 전 사전 동작 측정 (Measure Before Modifying)**: 변경 전 동작을 숫자로 먼저 측정하여 보고서에 명시.
3. **옛 방식 vs 새 방식 비교 테스트 선행 (Parity Test First)**: 변경 전 50판 이상 시드에서 차이 0건 확인 및 의도적 버그 주입 시 실패 확인.
4. **원본 함수 직접 열람 (Inspect Implementation Source)**: 값 생성 로직 원본 직접 확인.
5. **저장·전송 데이터 크기 상한 테스트 (Enforce Size Limits)**: 리플레이 v2 30KB 이하, 지문 64자 이하, GameBoard 800줄 이하, any 85건 이하 유지.
6. **추측 금지 및 불일치 시 즉각 중단 (No Guessing, Halt on Ambiguity)**: 코드와 지시서가 다르면 즉시 멈추고 질문.

## 2. 작업 보고서 및 교차 검토 규칙 (클로드 협업 기준)
1. **위치·이름**: `_docs/작업보고서/안티그라비티/작업내역_보고서(안티그라비티)_<주제>_<YYYY-MM-DD>.md` (작업마다 새 파일 생성, 기존 파일 덧붙이기 금지)
2. **머리말**: 제목 다음 줄에 `> 작성: Antigravity · <날짜> · 브랜치 \`dev\` · 커밋 \`<해시>\`` 및 `> 기준 문서: <이어받거나 검토한 보고서 경로/커밋>` 기재
3. **양식**: 맨 앞에 `## 0. 요약`(3~5줄) → GEMINI.md 보고서 1~9절 → `## 확인하지 못한 것` → `## 클로드 검토 요청` 순으로 작성
4. **변경 내역 표**: 변경 파일마다 `파일 경로 · 함수/컴포넌트 · 무엇을 왜 바꿨는지` 표 작성 (복수 커밋 시 커밋별 분리)
5. **근거 의무**: 테스트 파일·테스트 이름과 명령 실행 결과 원문(통과/실패 수) 기재 ("테스트 통과" 요약 금지)
6. **측정 명령 통일**:
   - 줄 수: PowerShell `(Get-Content <파일> | Measure-Object -Line).Lines`
   - 린트/테스트/빌드: `npm run lint -- --quiet`, `npm test`, `npm run build`
   - `any` 개수 (`CLAUDE.md` 2절): `grep -rnE ":\s*any\b|as any|\[key: string\]: any|@ts-ignore|@ts-expect-error" src | wc -l`
7. **확인하지 못한 것**: 실제 브라우저, 모바일 실기기, 2인 대전, AI 대전 판수 등 미확인 항목 별도 절 명시
8. **클로드 검토 요청**: 마지막 절에 틀릴 위험이 큰 지점을 `파일:함수` 단위로 2~5개 명시 (카드 객체 직접 변경, 턴 종료·선택 대기 흐름, 저장 형식 변경 등)
9. **커밋 단위·메시지**: 논리적 변경 하나에 커밋 하나, 메시지 형식은 `type(scope): 요약`
