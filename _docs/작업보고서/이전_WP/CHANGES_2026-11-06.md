## 2. 적용 방법

1. `changed-files.zip`을 프로젝트 루트에 풀어 덮어씁니다(경로 그대로). 또는 `changes.patch`를 `git apply`로 적용합니다(바이너리인 `public/effects/attack/*`는 zip에서 복사).
2. `npm install` (devDependency로 `vitest` 추가됨).
3. `npm test` → 32개 통과 확인.
4. `npm run dev`로 확인 후 `npm run deploy:cf`. 배포 스크립트가 이제 `npm test`를 먼저 실행하며, 테스트가 실패하면 배포하지 않습니다.

## 3. 배포 시 알아둘 것

- **서비스 워커 캐시 이름 변경:** `wuthering-tcg-v2.2.1` → `wtcg-app-v2.3.0`(앱) + `wtcg-static-v1`(카드·오디오·이펙트). 기존 사용자는 이번 배포 직후 **한 번만** 정적 파일을 다시 받습니다. 이후에는 `APP_CACHE` 버전을 올려도 정적 파일 캐시는 유지됩니다.
- **D1 테이블은 자동 생성:** `community_items`, `mp_rooms`는 API 첫 요청 때 `CREATE TABLE IF NOT EXISTS`로 만들어집니다. `schema.sql`에도 추가했으니 수동으로 실행해도 됩니다.
- **커뮤니티 데이터 자동 이전:** 게시판·덱·리플레이 요약은 첫 요청 때 `community_data`의 JSON에서 새 테이블로 옮겨집니다. 원본 `community_data` 행은 **지우지 않고 백업으로 남깁니다**. 배포 전 `wrangler d1 export`로 백업을 권장합니다.
- **SPA 폴백 제거:** `_redirects`의 `/* /index.html 200`을 지웠습니다. 앱은 해시 라우팅(`#battle-stage` 등)만 쓰므로 영향이 없어야 합니다. 다만 `도메인/경로` 형태 링크를 외부에 공유한 적이 있다면 이제 404가 됩니다.
- **원본에서 이미 실패하던 엔진 테스트 5개**는 `tests/engine-scripts.test.ts`의 `KNOWN_FAILING`에 `it.fails`로 표시했습니다(통과로 집계되지만, 고쳐지면 오히려 실패해서 목록에서 빼라고 알려줌). 의도된 동작 변경인지 버그인지 확인이 필요합니다.
  - `test_duplicate_upgrade_guard.ts`: Duplicate choice was not blocked
  - `test_shorekeeper_clash_heal.ts`, `test_shorekeeper_intro_combo_heal.ts`: 파수인 Lv.2 회복 드로우 시 `lastEffectDraw` 미생성
  - `test_shorekeeper_switch.ts`: BP01-008 교체 시 `lastEffectDraw` 미생성
  - `test_user_feedback_fixes.ts`: SELECT_EFFECT_UPGRADE에서 `lastUpgrade`가 설정됨

**주의:**
- 엔진 난수는 **모듈 전역 상태**입니다. 한 페이지에서 동시에 두 게임의 엔진을 돌리면 시퀀스가 섞입니다(현재 앱 구조에서는 해당 없음).

## 6. 직접 확인할 것 (브라우저)

1. **AI전 한 판:** 전투 진입 시 BGM이 끊기지 않는지, 카드가 검게 나오지 않는지. 개발자도구 Network에서 전투 진입 후 `/audio/` 요청이 몇 개씩 순차로 나가는지.
2. **격돌:** 대미지 1~2 / 3~4 / 5 이상에서 승자 캐릭터 스프라이트가 패자 카드 위에 나오고, 오른쪽 승자일 때 좌우가 뒤집히는지. 타격음이 이펙트 타격 순간과 맞는지. 표시 크기(360px)가 화면에 맞는지(`AttackFx`의 `size`로 조절).
3. **연격·리플레이:** 연격 단계별 스프라이트, 리플레이 대미지 스텝의 스프라이트.
4. **멀티 방:** 방 만들기 → 다른 브라우저 목록에 12초 안에 표시, 방장 탭을 닫으면 60초 안에 사라짐.
5. **게시판·공유 덱:** 배포 직후 기존 글·덱·리플레이가 그대로 보이는지(자동 이전). 글쓰기·수정·삭제·추천.
6. **재방문:** 두 번째 방문부터 카드·오디오가 `(ServiceWorker)`에서 오는지. 없는 주소(`/cards/없는파일.webp`)가 404인지.

## 8. 이 코드베이스에서 작업할 때의 규칙 (에이전트용)

- 엔진(`src/engine`, `src/data/cards.ts`)에서 `Math.random()`·id용 `Date.now()`를 새로 쓰지 말고 `src/engine/rng.ts`의 `engineRandom`·`engineTick`·`engineTag`를 쓴다. 쓰면 `tests/determinism.test.ts`가 실패한다.
- 전투 화면에서 카드 이미지는 `<img src={artUrl}>` 대신 `<CardArt artUrl sizes="표시너비px" />`.
- 공격 연출은 `AttackFx`/`SpriteEffect`를 재사용하고, 스프라이트 교체 시 `FX_VERSION`을 올린다.
- 오디오 미리 받기는 `loadCustomServerFile(key, 'low')`(큐), 재생 직전 필요한 소리만 `'high'`.
- 커뮤니티·방 API의 응답 형식은 클라이언트가 그대로 의존하므로 바꾸지 않는다. 바꾸면 `tests/community-api.test.ts`, `tests/rooms-api.test.ts`를 함께 갱신.
- 변경 후 `npm test`와 `npm run build`를 둘 다 통과시킨다.

### 13-2. 수정
- **`src/engine/fxSink.ts` (신규):** 엔진 연출 신호 수집기. `emitUpgradeFx`, `emitEffectFx`, `drainEngineFx`, `resetEngineFx`. `rng.ts`처럼 모듈 전역이지만 게임 상태에는 저장하지 않는다. `step()` 시작 때 비우고 끝날 때 꺼낸다.
- **`src/engine/gameEngine.ts`:** 제출본에서 지운 연출 코드 28곳(레벨업 6, 효과 알림 21, 레벨업 연출 보류 1)을 `emit…Fx(…)` 호출로 복원했다. 객체 내용은 지우기 전과 같다.
  - 대결 결과창이 닫힐 때(`proceedAfterClashReveal`) 첫 효과를 알림으로 띄우던 동작은 `clashResult.triggeredEffects[0]`로 복원했다(예전 `deferredEffectEvent`).
  - `resolvePendingChoice`의 `battleStepEffects` 누적은 그 함수 안에서 새로 나온 마지막 효과 알림으로 복원했다(예전과 같은 규칙).
  - `GameState`에는 연출 필드를 다시 넣지 않았다(4개 삭제 유지).
- **`src/engine/step.ts`:**
  - `diffEvents(prev, next, engineFx)`: UPGRADE는 엔진 신호 그대로, EFFECT_TRIGGERED는 액션당 마지막 1건(예전과 같은 규칙).
  - 리더 교체 판정의 "레벨업으로 인한 리더 칸 변경 제외"도 엔진 신호 기준으로 바꿨다.
  - 로그 기반 알림 코드와 칸 레벨 추정 코드는 삭제했다.
- **멀티:**
  - 게스트는 `step`을 돌리지 않아 이 신호를 알 수 없다. 그래서 호스트가 레벨업·효과 알림 이벤트를 모아 `SYNC_GAME_STATE.fxEvents`(선택 필드)로 함께 보낸다.
  - `PeerSource.receiveState(state, hostFxEvents)`는 같은 id를 1번만 처리한다. 구버전은 이 필드를 무시한다.
- **연출 큐 (`fxQueue.ts`, `fxRegistry.tsx`):**
  - 효과 알림 토스트·회복 숫자는 `lane: 'ambient'`(별도 레인)로 돌린다. 순서 큐에 줄을 서면 4초짜리 토스트 뒤에 효과 드로우(엔진이 완료를 기다리는 관문)가 밀려 게임이 멈추기 때문이다. 새 알림이 이전 알림을 대체한다(예전 화면과 같음).
  - 효과 알림은 대결 결과창이 닫힐 때까지 기다린다(`waitFor`).
  - 토스트 컴포넌트에서 렌더 중 `setTimeout`을 호출하던 것을 제거했다(표시 시간은 큐 타이머가 관리).
- **리플레이 크기:**
  - `stateFingerprint`를 상태 JSON의 짧은 해시(`fp1-…`, 약 30자)로 바꿨다. v2는 한 판 약 0.45MB에서 **약 5KB**가 됐다.
  - 예전 형식(전체 JSON) 지문도 `fingerprintMatches`로 비교된다.
- **서버 (`functions/api/community.ts`):** v2 **자체** 크기로 판단한다(`MAX_REPLAY_V2_BYTES` = 256KB). 로그가 커도 v2는 저장된다.
- **로컬 저장 (`replayManager.ts`):** `writeReplayList` — 저장 공간이 부족하면 가장 오래된 리플레이부터 빼고 다시 시도한다. 새 리플레이는 반드시 저장된다.
