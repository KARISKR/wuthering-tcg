## 2. 세부 작업 내역 및 변경된 파일 목록

### 2.1 신규 생성 파일
1. **`src/battle/source.ts`**
   - 통합 전투 소스 인터페이스 `BattleSource` 정의:
     ```ts
     export interface BattleSource {
       getState(): GameState;
       subscribe(listener: (state: GameState, events: GameEvent[]) => void): () => void;
       dispatch(action: GameAction): void;
       readonly kind: 'local' | 'peer-host' | 'peer-guest' | 'spectator' | 'replay';
     }
     ```
2. **`src/battle/LocalSource.ts`**
   - 싱글/AI 대전용 어댑터 클래스.
   - `dispatch(action)` 시 `step(state, action)`을 React 렌더링/업데이터 밖에서 독립 실행하여 StrictMode 더블 인보크로 인한 다중 이벤트 방출 방지.
   - 액션 1회당 등록된 구독자들에게 `(state, events)`를 정확히 1회 커밋 통지.
3. **`src/battle/PeerSource.ts`**
   - 멀티플레이 P2P(방장/게스트/관전자) 어댑터 클래스.
   - 구버전 클라이언트 호환성을 위해 기존 메시지 프로토콜(`DISPATCH_ACTION`, `SYNC_GAME_STATE` 등) 원본 형식 100% 보존.
   - `gameActionToMultiplayerAction`: `GameAction`을 네트워크 액션 타입/페이로드로 직렬화.
   - `multiplayerActionToGameAction`: 수신된 네트워크 액션을 엔진 `GameAction`으로 안전하게 역직렬화 (신규 `any` 없이 완전 타입 정의).
   - 게스트/관전 모드에서 상태 수신 시 `diffEvents(prev, next)`를 통해 이벤트를 합성하여 방출하며, 동일 상태 중복 수신 시 이벤트 0개 방출 보장.
4. **`src/battle/ReplaySource.ts`**
   - 리플레이 v2 전용 읽기 전용 어댑터 클래스.
   - Step A에서 구현한 `replayFrames(v2)`를 기반으로 프레임 스트림 탐색 지원 (`stepForward`, `stepBackward`, `playToEnd`, `getState`).
   - `dispatch` 호출 시 엔진 상태를 변경하지 않는 읽기 전용 불변성 보장.
5. **`src/battle/useBattleSource.ts`**
   - `BattleSource`를 React 컴포넌트에 안전하게 바인딩하는 전용 훅.
   - `subscribe` 리스너를 통해 상태 및 이벤트 묶음을 React 상태(`gameState`, `lastEvents`)로 동기화.
6. **`tests/battle-source.test.ts`**
   - `LocalSource`: 20개 연속 액션 디스패치 시 구독자 호출 횟수(20회) 및 상태 전이 횟수 일치, 방출된 모든 이벤트 ID 중복 없음 검증.
   - `PeerSource`: 게스트 모드에서 동일한 상태 참조 2회 연속 수신 시 2번째 수신에서 방출 이벤트 0개 검증, 게스트 dispatch 시 로컬 step 미실행 및 원격 위임 검증.
   - `ReplaySource`: 경기 끝까지 재생(`playToEnd()`)한 최종 상태 지문이 `replayToEnd(v2)` 결과와 100% 일치 검증.

## 4. 멀티플레이 게스트/방장 연출 순서 및 동작 확인 결과
- **확인 항목**: 멀티플레이 시 게스트 화면에서 연출(격돌·연격·레벨업)이 방장과 동일한 순서로 발생하는지 여부
- **확인 결과**: **확인함 (동일)**
  - 방장이 `step()`을 통해 생성한 새로운 상태가 `SYNC_GAME_STATE`로 게스트에게 전달됩니다.
  - 게스트의 `PeerSource`가 수신 즉시 직전 상태와 신규 상태 간의 `diffEvents(prev, next)`를 계산합니다.
  - 계산된 이벤트 배열은 `PHASE_CHANGED` → `CLASH_REVEAL` → `DAMAGE/HEAL` → `UPGRADE` → `LEADER_SWITCH` → `COMBO_STRIKE` 순서의 불변 규칙에 따라 방장과 동일한 순서로 구독자(UI 및 오디오)에게 방출됩니다.
  - 동일한 상태가 중복 수신될 경우 중복 연출을 방지하기 위해 빈 이벤트 배열(`[]`)이 방출됨이 단위 테스트로 입증되었습니다.
