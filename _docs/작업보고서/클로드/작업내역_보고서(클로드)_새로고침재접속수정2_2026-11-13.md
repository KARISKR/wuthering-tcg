## 0. 요약

- 브라우저 두 개를 따로 띄우는 재현 스크립트로 증상을 그대로 재현했다(playwright-core + 로컬 vite + 공용 PeerJS 서버). 원인은 세 가지였다.
  1. **방장이 새로고침하면 참가자가 재접속을 한 번도 시도하지 않았다.**
     - 참가자의 4초 간격 재시도 타이머는 의존성에 `GameBoard`가 렌더마다 새로 만드는 함수 2개를 넣었다.
     - 끊김 카운트다운이 1초마다 화면을 다시 그리니까 타이머가 1초마다 새로 만들어졌고, 4초에 한 번도 닿지 못했다.
     - 그래서 참가자는 "상대방 재접속 대기 중"에 계속 머물렀다. 사용자가 본 증상이 이것이다.
  2. **새로고침하면 리더 선택·멀리건 단계에서 주사위 화면이 다시 떴다.**
     - `App`이 저장된 대전을 `GameBoard`의 `initialSavedSession` 입력으로 넘기지 않았다.
     - 그래서 `GameBoard`는 새 게임으로 시작했다. "주사위 진행 중" 값은 항상 켜져 있었고, 방장은 저장분 대신 새 게임 상태로 시작했다.
  3. **방장이 리더 선택·멀리건 중에 새로고침하면, 참가자가 이미 보낸 선택을 잃었다.**
     - 참가자 화면은 "선택 완료, 대기"로 남아 양쪽이 서로를 기다릴 수 있었다.
- 수정 뒤 재현 결과:
  - 방장 새로고침과 참가자 새로고침 두 경우 모두 양쪽이 다시 연결된다(`CONNECTED`). 재접속 대기 화면은 뜨지 않는다.
  - 멀리건 단계가 유지되고, 양쪽이 멀리건을 마치면 **둘 다 `DRAW_PHASE`로 진행**한다.

## 3. 옛/새 비교 결과

| 시나리오 (멀리건 단계에서 새로고침) | 옛 동작 | 새 동작 |
|---|---|---|
| 방장 새로고침 → 40초 뒤 | 참가자 영구 "재접속 대기", 방장 `WAITING_FOR_GUEST` | 양쪽 `CONNECTED`, 오버레이 없음 |
| 방장 새로고침 → 양쪽 멀리건 | 진행 불가 | 양쪽 `DRAW_PHASE` |
| 참가자 새로고침 → 참가자 화면 | 주사위 화면 | 멀리건 화면 (캡처 확인) |
| 참가자 새로고침 → 양쪽 멀리건 | — | 양쪽 `DRAW_PHASE` |

- **비교 방법**: 재현 스크립트(임시 폴더 `scratchpad/mp/flow.mjs`, `WHO=HOST|GUEST`). 저장소에는 넣지 않았다(공용 PeerJS 서버와 설치된 Chrome이 필요해 CI에서 못 돌린다).
- **일부러 버그를 넣었을 때 실패 확인**: 따로 넣지는 않았다. 수정 전 코드에서 같은 스크립트가 위 "옛 동작"으로 실패한 것을 확인했다.
- **도중에 생긴 문제**: 복구 효과의 의존성에 setter를 넣었다가 "Maximum update depth exceeded"로 화면이 비는 것을 스크립트가 잡았다. 의존성에서 빼서 해결했다.
