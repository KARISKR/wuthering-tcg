### 10-1. 전체 흐름

```
#sandbox → SandboxSetup(설정 화면) → buildSandboxState(config) → GameState
        → App: setSandboxState(state), battleMode='SOLO_DUAL', currentView='BATTLE'
        → GameBoard initialState={state}
        → useGame(..., 8번째 인자 = initialSavedSession?.lastGameState ?? initialState)
        → LocalSource가 그 상태에서 시작 (선공 주사위 연출은 생략)
```

- 멀티플레이 저장 세션(`initialSavedSession`)과는 다른 경로다. App은 `battleMode === 'SOLO_DUAL'`일 때만 `initialState`를 넘긴다.
- `sandboxState`는 `handleExitBattle`, `handleStartGame`, `handleStartMultiplayerMatch`에서 `null`로 지운다. 그래서 일반 배틀에 남지 않는다.
- 배틀이 시작된 뒤에는 일반 1인 2역과 똑같다. 엔진(`step`), 효과, 연출, 모달이 모두 실제 코드다. 샌드박스 전용 규칙은 없다.

### 10-3. `buildSandboxState(config)` 규칙 (`src/engine/sandbox.ts`)

순수 함수다. 같은 설정과 시드면 항상 같은 상태가 나온다. `tests/engine-purity.test.ts` 대상이다.

| 설정 | 동작 |
|---|---|
| `p0`/`p1.leader` | 캐릭터 코드 배열, **아래(Lv.0)부터 위로**. 마지막이 맨 위 카드, 나머지는 `underlyingCards` |
| `leftSupport`/`rightSupport` | 같은 형식. 생략하거나 빈 배열이면 빈 슬롯 |
| `hand` | 손패를 이 카드로 **바꾼다**. 생략하면 스타터 덱 첫 5장 |
| `deckTop` | 액션 덱 맨 위에 순서대로 놓는다 (덱 위 공개·드로우 효과 시험용) |
| `trash` | 트래시(`dropZone`)를 이 카드로 채운다 |
| `concerto` | 협주 장수. 덱 맨 아래 카드로 채운다 |
| `hp`, `dominance` | 체력, 【우세】 |
| `activePlayer` | 턴 플레이어 (기본 0). 선공도 같은 값 |
| `startPhase` | `ACTION_PHASE` / `CLASH_SET` / `COMBO_STEP` |
| `comboCount` | `COMBO_STEP`에서 턴 플레이어의 남은 연격 횟수. 생략하면 무제한 (적색 승리처럼) |
| `seed` | 기본 1 |

그 밖의 고정값과 한계:

- 바탕은 `createInitialGameState('STARTER_ROVER','STARTER_CHIXIA','SOLO_DUAL', …)`다. 그래서 **액션 덱 나머지는 스타터 덱 40장**이다. `hand`를 주면 그 카드는 덱 밖에서 따로 만들어지므로, 덱에서 빠지지 않는다.
- 레벨업용 캐릭터 덱은 필드 캐릭터들의 Lv.1·2 카드 중 아직 쓰지 않은 것이 코드별 1장씩 자동으로 들어간다.
- `turn: 2`, `firstTurnDrawCompleted: true`로 시작하므로 첫 턴 예외 규칙이 없다. 로그 맨 위에 `log-sandbox-start`가 붙는다.
- 카드 id 형식은 `sbx-p{0|1}-{leader|left|right|hand|top|trash|cdeck}-{n}-{code}`다. 테스트에서는 `hand.find(c => c.code === X).id`로 찾으면 된다.
- 액션 에리어(`actionArea`)는 비우고, 대결 카드도 세트되지 않은 상태로 시작한다. `CLASH_REVEAL`이나 `pendingChoice` 상태로 바로 시작할 수는 없다. 그 직전 단계에서 시작해 `step`으로 진행한다.
- 모르는 카드 코드를 넣으면 `샌드박스: … 코드를 찾을 수 없습니다: {code}`를 던진다.
- 카드 코드는 `src/data/cards.ts`의 `ALL_CHARACTERS`(캐릭터)와 `ACTION_CARD_TEMPLATES`(액션)에서 찾는다. 액션 카드는 `getHighestRarityActionCard(code)`로 만든다.

### 10-4. 쓰는 법 ① 테스트로 (먼저 권장, 빠르고 남는다)

버그 재현이나 효과 확인은 `tests/sandbox-scenarios.test.ts`처럼 「설정 → step → 기대값」으로 쓴다.

```ts
import { buildSandboxState } from '../src/engine/sandbox';
import { step } from '../src/engine/step';

let s = buildSandboxState({
  p0: { leader: ['BP01-018'], hand: ['SD01-020'], deckTop: ['SD01-021'] },
  p1: { leader: ['BP01-027'], hand: ['SD01-007'] },
  startPhase: 'CLASH_SET',
});
const id = (p: 0 | 1, code: string) => s.players[p].hand.find((c) => c.code === code)!.id;
s = step(s, { type: 'SET_CLASH_CARD', playerIndex: 0, cardId: id(0, 'SD01-020') }).state;
s = step(s, { type: 'SET_CLASH_CARD', playerIndex: 1, cardId: id(1, 'SD01-007') }).state;
s = step(s, { type: 'RESOLVE_CLASH' }).state;           // 판정 전 효과가 있으면 pendingChoice가 생긴다
s = step(s, { type: 'RESOLVE_PENDING_CHOICE', chosenCardIds: ['2'] }).state;
```

- 자주 쓰는 액션(`src/engine/events.ts`의 `GameAction`): `SET_CLASH_CARD`, `RESOLVE_CLASH`, `PROCEED_AFTER_CLASH`, `COMBO_ATTACK`(`discardForBonusDmgId` 선택), `FINISH_COMBO`, `RESOLVE_PENDING_CHOICE`, `UPGRADE`, `CHARGE_CONCERTO`, `END_TURN`.
- 실행: `npx vitest run tests/sandbox-scenarios.test.ts`
