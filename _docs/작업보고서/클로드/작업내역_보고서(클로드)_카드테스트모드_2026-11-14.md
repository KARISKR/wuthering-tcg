## 0. 요약

- 관리자 전용 `#sandbox` 화면을 추가했다. 양쪽 리더·서포터(레벨업 스택 포함), 손패, 덱 위 카드, 트래시, 협주 장수, 체력, 【우세】, 턴 플레이어, 시작 단계(액션 / 대결 세트 / 연격 + 남은 연격 횟수)를 고르고 「시작」을 누르면 실제 `GameBoard`가 그 상태의 1인 2역(SOLO_DUAL)으로 열린다.
- 상태는 순수 함수 `buildSandboxState(config)`(`src/engine/sandbox.ts`)가 만든다. 화면과 테스트가 같은 함수를 쓴다. 시나리오 테스트 2개(방랑자 배틀 효과, 강공격 버리기)와 생성 테스트 2개를 남겼다.
- 상태는 `GameBoard`의 새 prop `initialState`로 넘긴다. 멀티플레이 저장 세션(`initialSavedSession`)과는 다른 경로다. SOLO_DUAL일 때만 쓰고, 다른 배틀을 시작하거나 배틀에서 나가면 지운다.
- 관리자 확인은 기존 `isUserAdmin()` / `verifyBoardPassword()`를 그대로 쓴다. 번들에 비밀 값은 넣지 않았다. 로컬 `npm run dev`에는 Pages Functions가 없어서 개발 빌드(`import.meta.env.DEV`)에서만 관리자 확인을 건너뛴다. 배포 빌드에서는 이 값이 false라 확인 단계가 그대로 남는다.
- `npm test` 191개 통과, 린트 오류 0, 빌드 성공, `any` 82 (상한 85). 커밋·푸시는 하지 않았다.

## 7. 브라우저 확인 (로컬 `npx vite --port 5181`)

장면 1 — 방랑자(여) Lv.0 배틀 효과 (대결 세트부터)
- 설정: P1 방랑자(여) Lv.0, 손패 스캔/소리의 변화·강공격/펑펑, 덱 맨 위 로프, 협주 3 · P2 치샤 Lv.0, 손패 펑펑.
- 「시작」 → TURN 2 / CLASH SET 화면이 열렸다. 협주 3/10, 손패도 설정과 같았다.
- P1 스캔을 더블클릭하자 화면이 P2로 자동 전환됐고, P2 펑펑을 세트했다.
- 방랑자 선택 창이 대결 카드 띠("내 대결 카드 스캔 녹색 · 속도 5 · 피해 0 VS 상대 대결 카드 펑펑·일반 공격 적색 · 속도 6 · 피해 1")와 함께 떴다.
- 「2장 공개 후 패 추가」 → P1 손패가 4장(강공격, 펑펑, **로프**, 진동)이 됐다. 덱 위로 지정한 로프가 들어왔다. 이어서 적색이 이겨 P2 연격 단계로 넘어갔다.

장면 2 — 소리의 변화·강공격 (연격 단계부터, 연격 무제한)
- 「시작」 → COMBO STRIKE 연출 뒤 P1 연격 단계(∞)가 열렸다.
- 강공격을 더블클릭하자 「소리의 변화·강공격 — 버릴 패 선택」 창(스캔 / 펑펑, 취소 / 버리지 않고 공격)이 떴다.
- 스캔 선택 → "방랑자(여)의 공격으로 2 데미지" (카드 데미지 1 + 1). P2 HP 20→18, P1 트래시는 스캔·소리의 변화·강공격 2장이었다.
- 참고: 연출을 넘기려고 화면 가운데를 클릭한 뒤 P1 연격이 끝나고 P2 드로우 단계로 넘어갔다. P1 손패에 적색 펑펑이 남아 있었는데 왜 연격이 끝났는지는 따로 확인하지 않았다(클릭이 다른 버튼에 닿았을 수 있다). 샌드박스가 아니라 기존 연격 흐름 쪽의 일이라 고치지 않았다.
