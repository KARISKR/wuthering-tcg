## 클로드 검토 요청
- `functions/api/community.ts:onRequest` (`GET /api/community?type=board&postId=...`) 및 `src/components/CommunityBoard.tsx:unlockSecretPost`:
  - 아직 관리자 인증(`wuthering_admin_key`)이 로컬스토리지에 저장되지 않은 상태에서 운영자가 비밀글을 클릭해 비밀번호 입력 모달에 `ADMIN_KEY`를 입력하면, `fetchFeedbackPostDetail(postId, pw.trim())`는 `X-Board-Password` 헤더로만 값을 보내고 `X-Admin-Key` 헤더는 비어 있게 됩니다. 서버 `readAuth`는 `adminKey` 인자만 `env.ADMIN_KEY`와 비교하므로, 비밀글 비밀번호 입력창에 `ADMIN_KEY`를 직접 입력했을 때도 열리게 하려면 단건 조회에서 `X-Board-Password`가 `env.ADMIN_KEY`와 일치하는지 함께 허용하거나 `unlockSecretPost`에서 `verifyBoardPassword`를 거치는지 검토가 필요합니다.
- `src/components/CommunityBoard.tsx:handleDelete` 및 `handleDeleteComment`:
  - `post?.hasPassword` 또는 `comment.hasPassword`가 `true`일 때 이미 관리자 인증(`isUserAdmin() === true`)이 된 상태라면 `ensureBoardAuth(true, ...)`가 프롬프트 없이 즉시 `true`를 반환하고 `else if (!window.confirm(...))` 분기를 건너뛰어, 관리자가 비밀번호 걸린 일반 글/댓글의 삭제 버튼을 누르면 확인창(`window.confirm`) 없이 즉시 삭제됩니다. 관리자일 때도 삭제 전 `window.confirm`을 거치게 할지 검토를 요청합니다.
- `functions/api/community.ts:savePost`:
  - 권한 없는 요청의 `shortcut:` 분기에서 `bump(cur, next)`가 `+1` 증가만 허용하므로, 비밀번호가 설정된 남의 글에 추천/비추천을 눌렀다가 다시 눌러 취소(`-1`)할 때는 서버 값이 줄어들지 않습니다(클로드 보고서 9절에 명시된 사항과 동일하며, 추후 `likePost`/`dislikePost` 액션 분리 시 해소 가능).
