## 0. 확정된 결정 (사용자 확인 완료)

| 항목 | 결정 |
|---|---|
| 지원 방향 | **가로만 지원.** 세로는 대결·리플레이·**튜토리얼 전투** 모두 차단 ("세로로 계속 보기" 제거) |

### 원인 (코드 근거)
- `BattleLayout.tsx:123` — 중앙 보드 전체에 `zoom: arenaZoom × viewportScale`.
- `useBattleViewport.ts` — `viewportScale = min((innerHeight−38)/1000, availW/1080)`. 가로 폰은 높이가 360~430이라 **항상 높이 제한**으로 0.34~0.39.
- `OpponentFieldArea.tsx:257` — 진영 그리드가 `grid-cols-[250px_1fr_250px]`, `max-w-[1580px]`. 실제 펼침 폭이 1080이 아니라 약 1540 → 폭이 남아도 높이 때문에 못 키움.
- `HandView.tsx:287` — 손패 카드 `w-[122px] h-[172px]` 고정 + `min-h-[170px]` → zoom 후에도 하단 넘침.
- `BattleLayout.tsx:146` — 모바일 퀵 액션 바가 `fixed bottom-2.5 right-2`로 손패 줄 위에 겹침.
- `useBattleViewport.ts:checkIsMobileBattle` — `innerWidth < 1024`만으로도 모바일 판정 → 작은 PC 창도 모바일 모드.

## 2. 레이아웃 모드

### 2-1. 판정 함수 (순수 함수, 테스트 대상)

```ts
type BattleLayoutMode = 'portrait-blocked' | 'phone-landscape' | 'standard';

function decideBattleLayoutMode(input: {
  width: number; height: number;
  coarsePointer: boolean;      // matchMedia('(pointer: coarse)')
  forced?: 'phone-landscape';  // ?layout=phone (개발·측정용 강제)
}): BattleLayoutMode
```

| 조건 (위에서부터 먼저 맞는 것) | 모드 |
|---|---|
| `forced === 'phone-landscape'` | phone-landscape |
| `coarsePointer && height > width` | portrait-blocked |
| `coarsePointer && height < 500` | phone-landscape |
| 그 외 (PC, 태블릿 가로, 작은 PC 창) | standard (현재 레이아웃 유지) |

- 높이 500을 경계로 둔 근거: 가로 폰 실측·대표 기종 높이 360~430, 태블릿 가로 최소 높이 ≈ 744 (iPad mini). 사이에 여유가 크다.
- 작은 PC 창은 `coarsePointer=false`라 standard → 지금처럼 zoom 축소 (이번 범위 밖).
- 기존 `#m-battle` 해시 강제 판정은 `?layout=phone`으로 대체할지 유지할지 3단계 착수 시 확인 (해시는 `App.tsx:getBattleHash`가 자동 설정 중).
- 기존 `isMobileBattle`은 사용처가 많으므로 당장 지우지 않고 `mode !== 'standard'`로 **파생값**으로 남긴다. 사용처 전수 목록은 3단계에서 grep으로 측정.

### 2-2. phone-landscape 화면 분할 (844x390 기준 예시)

```
┌───────────────────────── 상단 바 36px (턴·페이즈·항복·메뉴) ─────────────────────────┐
│ safe-area-left │  상대 진영 (≈34%)  │  대결 (≈32%)  │  내 진영 (≈34%)  │ safe-area-right │
│                │  HP·협주·손패 수    │  상대 대결 슬롯 │  HP·협주          │                 │
│                │  지원 리더 지원     │  턴/페이즈      │  지원 리더 지원    │                 │
│                │  덱·트래시 배지     │  내 대결 슬롯   │  덱·트래시 배지    │                 │
│                │                    │  [주 액션 버튼]  │                   │                 │
├──────────────────────── 손패 띠 56px (살짝 보임) ──────────────────────────────────┤
```

- 각 열은 `flex: 1 1 0` + `min-width`로 폭 667~932 차이를 흡수. 양옆 빈 공간 없음.
- 열 안 캐릭터 카드 폭은 CSS 변수 `--phone-card-w`로 계산: `min(열 폭 / 3.3, (가용 높이 − 고정 UI) / 1.4 × 5/7)`. 844x390에서 약 80~90px.
- **zoom을 쓰지 않는다.** 글씨는 고정 px(아래 2-3), 카드는 `--phone-card-w`로만 크기 조절.
- 노치: 아이폰 가로에서 좌우 safe-area 약 47px → 실질 폭 844 → 약 750. 열 계산은 safe-area를 뺀 폭 기준.

### 2-3. 글씨·터치 규칙 (phone-landscape 전용)

| 대상 | 최소 |
|---|---|
| 읽어야 하는 글씨 (이름, 수치, 버튼, 안내) | 10px, 수치(HP·협주·장수)는 11px |
| 버튼·탭 영역 | 44×44px (보이는 크기가 작으면 투명 패딩으로 확장) |
| 장식 글씨 (✦, 워터마크 등) | 예외. `aria-hidden="true"`를 붙이고 측정에서 제외 |
| 보드 위 카드 효과문 | 보드에서는 표시하지 않음 → 탭/길게 누르기 시 카드 상세 모달 (`showMobileCardModal` 재사용) |

## 3. 손패 (phone-landscape)

| 상태 | 표시 | 들어가는 조건 | 나가는 조건 |
|---|---|---|---|
| peek (기본) | 화면 하단 56px 띠. 카드 윗부분(코스트·속성·이름 앞부분) | 기본값, 카드 사용 직후, 바깥 탭, 아래로 쓸기, 상대 턴 시작 | 띠 탭 |
| expanded | 화면 높이 55~60% 패널. 카드 폭 90~110px 부채꼴, 뒤 보드 어둡게 | peek에서 탭 | 위 peek 조건 |
| selected (expanded 안) | 선택 카드 확대 + "사용 / 상세" 버튼 (44px 이상) | 카드 탭 | 다른 카드 탭, 사용, 닫기 |

- peek에서는 카드 개별 선택 불가 (띠 전체가 하나의 탭 영역) — 오터치 방지.
- 현재 `HandView.tsx:59` `isHandCollapsed`(접힘 시 `h-8`)가 있음 → 새로 만들지, 이 상태를 3값으로 확장할지 **5단계 착수 시 원본 확인 후 결정** (GEMINI 1-4).
- 대결 세트 단계·연격 단계처럼 손패에서 골라야 하는 시점에 들어가면 **자동으로 expanded** (확정).

## 4. 세로 차단 (portrait-blocked)

- 대상: `App.tsx:307` 조건에 **튜토리얼 전투 추가** (현재 `!isTutorialBattle`로 제외됨).
- `MobileOrientationGuard.tsx`
  - "세로 화면으로 계속 보기" 버튼·`isDismissed` 제거.
  - 판정을 `innerWidth < 820 && 세로` → `pointer: coarse && 세로`로 변경 (iPad 세로도 차단).
  - 가로 전환 버튼: `screen.orientation.lock` 지원 여부로 분기. 미지원(iPhone) 또는 lock 실패 시 버튼을 숨기고 회전 안내 + "회전 잠금 해제" 안내 표시.
  - 가로로 돌리면 자동으로 사라짐 (현재 동작 유지).
- 멀티플레이 중 안내가 떠 있어도 턴 타이머는 **계속 흐른다** (확정, 변경 없음).

## 6. 검증 방법

- 측정 스크립트로 단계마다 같은 표를 다시 뽑는다: zoom, 카드 영역 폭 비율, 하단 넘침, 글씨 크기 분포, 44px 미만 버튼 수, 고정 요소 겹침.

- 멀티플레이 메시지·저장 데이터·D1 스키마는 건드리지 않음 (UI 전용).

## 7. 결정이 필요한 것

1. **측정 스크립트를 저장소에 넣을지** — 넣으려면 `playwright-core`를 devDependency로 추가해야 함 (지금은 스크래치패드에만 설치). 넣으면 이후 단계 보고서에서 같은 명령으로 재현 가능.
2. ~~세로 안내 중 멀티플레이 턴 타이머~~ → **확정: 그대로 흐름** (멈추면 악용·동기화 문제가 더 큼).
3. ~~손패 자동 펼침~~ → **확정: 대결 세트·연격 등 손패에서 골라야 하는 단계에 들어가면 자동 expanded** (5단계 완료 기준에 포함).
4. **PWA manifest `orientation`** — `any` 유지 / `landscape`로 변경 (앱 전체가 가로 고정됨). 이번 범위 밖으로 둘지.
